# Phase 19 — UI Design Contract

> Visual and interaction contract for the WLED Strip Paint UI. Generated by gsd-ui-researcher from CONTEXT.md (D-01..D-22), the `sketch-findings-huepicturecontrol` skill (Sketches 001/002/003), and the existing Frontend tokens in `src/index.css`. Verified by gsd-ui-checker.

**Phase goal:** Users can visually paint LED channel ranges directly onto a strip representation in the WLED settings tab, and the resulting channels appear in the LightPanel for assignment to canvas regions via the same drag-drop workflow used for Hue segments. **Per-region** orientation is editable from a canvas popover anchored to the selected region (narrowed from per-assignment during plan-phase on 2026-05-14 to preserve D-22's single-gradient-per-region contract).

**Source-of-truth references** (consumers MUST read these alongside this contract):
- `.planning/phases/19-wled-strip-paint-ui/19-CONTEXT.md` — 22 locked decisions (D-01..D-22)
- `.claude/skills/sketch-findings-huepicturecontrol/references/canvas-and-overlays.md` — strip + popover specs
- `.claude/skills/sketch-findings-huepicturecontrol/references/zone-palette.md` — `channelColor(i)` formula
- `Frontend/src/index.css` — brand tokens (Geist Variable, `--accent #e8a000`, glass surfaces)

## Interaction Contract

This section is **load-bearing for the executor** and is not in the standard template — it documents interaction states the planner needs for tasks. It is referenced by the gsd-ui-checker under Dimension 2 (Visuals) and Dimension 6 (registry-adjacent — drag-drop payload contract).

### Strip canvas (`WledStripPainter`)
- **Empty drag (paint to create):** mousedown on empty space inside the strip → drag → mouseup commits a `POST /api/wled/devices/{id}/channels` with `{start_led, end_led}`. Overlap auto-splits per D-02 (backend handles, frontend just renders the response).
- **In-progress preview:** during drag, render a semi-transparent zone with the **next-index** `channelColor(N+1)` at 50% opacity over the strip (no DB write yet).
- **Click on existing zone:** selects the zone (visible state: `outline: 1px solid var(--accent); z-index: 2`). Selection drives the sidebar contents. Selection state lives in local component state (not Zustand) — single-source per `WledStripPainter` instance.
- **Drag on boundary handle:** mousedown on `.handle` (8px hit-zone) → drag → mousemove updates the shared boundary visually (clamped to neighboring zones' inner edges, min 1-LED width per side) → mouseup commits `PUT /api/wled/devices/{id}/channels/{id}` for both affected channels. Cursor: `ew-resize` over handle.
- **Zone collapse to 0 width via handle drag:** treat as a delete with cascade — D-21 DELETE endpoint, identical to sidebar delete (per CONTEXT.md "Claude's Discretion" bullet).
- **Hover on zone:** `filter: brightness(1.08)` — no color change, no outline change.
- **Hover on boundary handle:** handle visible line → `var(--accent)`; height grows 70% → 90%.

### LightPanel WLED section
- **Render order:** below the existing "Lights" section, above "Assignments". Section header `WLED` follows the existing `text-[11px] font-semibold text-muted-foreground uppercase tracking-wider` pattern.
- **Counter chip:** to the right of `WLED` header — `text-[11px] font-mono text-muted-foreground` (no thresholds per D-14). Shows total `M` = sum of channels across all enabled WLED devices.
- **Grouping:** one sub-block per WLED device. Device header style identical to the existing Hue light header — `rounded-lg px-2.5 py-1.5 bg-white/[0.03] border border-white/[0.06]`, device name `text-xs font-semibold`, device meta `text-[10px] text-muted-foreground font-mono` (`{ip} · {led_count} LEDs`).
- **Channel rows:** nested under each device with `ml-3 border-l-2 border-hue-orange/20 flex flex-col gap-0.5 pl-1` (mirrors Hue per-segment rows). Each row:
  - Circular chip (`w-2.5 h-2.5 rounded-full`) with `background: channelColor(channel.index)` on the left
  - Channel name `text-[11px] font-medium text-foreground/80` middle
  - `ch {channel.id}` indicator `text-[10px] text-muted-foreground font-mono` right
  - When assigned, second line `text-[10px] text-hue-amber/60`: `Assigned: {region.name}`
- **Drag-source payload (D-13, extends Hue payload — DOES NOT REPLACE):**
  - `wledChannelId: string` (channel database id)
  - `wledDeviceId: string` (parent device id)
  - `wledChannelName: string` (display name, e.g. `Channel 3`)
  - `entertainment_config_id: string` (active config; mirrors Hue payload's `configId`)
  - `e.dataTransfer.effectAllowed = 'copy'`
- **Cursor:** `cursor-grab`, active state `active:opacity-60`. Same as Hue rows.

### EditorCanvas drop handling (additive branch in `handleDrop`)
- Read `wledChannelId` from `e.dataTransfer.getData(...)`. If present (and `lightId` is empty/absent), branch into the WLED assignment path.
- POST/PUT to new endpoint `PUT /api/wled/assignments` with body `{region_id, wled_channel_id, entertainment_config_id, orientation: 'auto'}` (D-21, D-18).
- On 2xx: refresh `useRegionStore` regions (existing `setRegions(await fetchRegions())` pattern) so the popover and LightPanel reflect the assignment.
- Existing Hue branch is **untouched**.

### Region orientation popover (`RegionOrientationPopover`)
- **Open trigger:** `useRegionStore.selectedId` changes to a non-null value.
- **Close triggers (all four required):**
  1. Click outside the popover and outside the selected region
  2. Region deselect (`selectedId` → null)
  3. Selecting a different region (popover re-renders against new anchor)
  4. Explicit `×` button in popover header
- **Anchoring algorithm:** default = bottom-left of the selected region's bounding box, offset 12px down. Auto-flip:
  - If `popover.bottom > canvas.bottom - 8px`: flip above (beak on bottom edge, 24px from left)
  - If `popover.right > canvas.right - 8px`: shift left so right edge sits at `canvas.right - 8px`
  - If `popover.left < 8px`: shift right so left edge sits at `8px`
  - Beak position recomputed to stay aligned with the region's left edge (clamped to 16–264px from popover left)
- **Surface:** `background: rgba(20, 20, 35, 0.96); border: 1px solid var(--glass-border); border-radius: 8px; padding: 12px; box-shadow: var(--shadow-lg); backdrop-filter: blur(12px); z-index: 50; width: 280px`.
- **Layout (per-region, narrowed from per-assignment on 2026-05-14):**
  1. Title row — `{region.name} · {N} channels` + `×` close button
  2. `Sample axis` sub-label
  3. One 5-button segmented control (auto / → / ← / ↓ / ↑) — applies to ALL WLED channels assigned to this region
  4. `Channels in this region` sub-label
  5. Read-only list — each row: circular `channelColor(index)` chip + `{channel.name} · LEDs {start}–{end}` (mono). No per-row controls.
- **Segmented-control auto-save:** click handler immediately fires `PATCH /api/wled/regions/{region_id}/orientation?config={config_id}` with body `{orientation}` (D-21, D-22). One request updates every assignment row for the region in the current config. No "Apply" button. Optimistic UI update.

### Sidebar in Settings paint slot
- Lives **to the right of the strip canvas inside the `md:flex-[6]` slot**, NOT inside `WledDevicesPanel` (which keeps the device CRUD up top per sketch 001-A).
- Layout: `WledDevicesPanel` keeps its existing layout in the `md:flex-[4]` column; the **left column** (`md:flex-[6]`) is now split vertically into (top) the stack of strips and (bottom) the "Selected channel" sidebar group (~120px tall, glass surface, padding 12px).
- Selected-channel group is empty-state by default (`Select a zone on the strip to edit it.`) and populates when a zone is selected.

## Drag-Drop Payload Contract (Cross-Cutting)

**Critical for the executor.** Documented here because `EditorCanvas.handleDrop` is the single integration point and any regression silently breaks Hue assignment.

| Key | Type | Hue payload (existing) | WLED payload (Phase 19, additive) |
|-----|------|------------------------|-----------------------------------|
| `channelId` | string | Hue channel ID (numeric stringified) | (absent) |
| `channelName` | string | `{light.name} [{seg+1}/{seg_count}]` | (absent) |
| `lightId` | string | Hue light id | (absent) |
| `configId` | string | Entertainment config id | (absent) |
| `wledChannelId` | string | (absent) | WLED channel database id |
| `wledDeviceId` | string | (absent) | WLED device database id |
| `wledChannelName` | string | (absent) | `Channel {N}` or `Strip` or renamed value |
| `entertainment_config_id` | string | (absent — `configId` carries it) | Active entertainment config id |
| `effectAllowed` | DataTransferEffectAllowed | `'copy'` | `'copy'` |
