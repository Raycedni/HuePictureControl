<objective>
Surface the current streaming state's active entertainment config and device path on the `/ws/status` WebSocket so the frontend can reflect true streaming state on page load (BFIX-02) and so the persistence layer (16-01) has a complementary live surface. This plan extends `StatusBroadcaster._metrics` with two new fields (`active_config_id`, `active_device_path`), accepts them as optional kwargs on `push_state()` and `update_metrics()`, and wires `StreamingService` to pass them on every state transition — setting real values on `starting`/`streaming`/`reconnecting` and clearing them to `None` on `idle`/`error`.

Purpose: BFIX-02 — "On page load while streaming is active elsewhere, the dropdown reflects the streaming state correctly rather than a default/idle state." Plan 16-03 consumes these fields in Zustand; without them, the frontend cannot distinguish "idle" from "streaming to config X".

Output: Extended broadcaster surface, instrumented StreamingService transitions, and tests proving the payload contract holds at every state edge.
</objective>
