<objective>
Add per-camera entertainment-zone persistence at the backend DB and REST layers. This plan creates the `camera_last_zone` table (new in this phase), exposes the write surface via `PUT /api/cameras/last-zone/{stable_id}`, extends the existing `GET /api/cameras` response so each device carries `last_entertainment_config_id`, and updates `known_cameras.last_seen_at` whenever the last-zone is written OR a camera assignment is written (per D-10, "most-recently-touched camera" tracking — bumped on every camera-dropdown change, which flows through both endpoints).

Purpose: This is the persistence foundation for BFIX-01 — "After selecting an entertainment config and reloading the page, the same config is pre-selected in the dropdown without manual re-selection." The frontend plan (16-03) reads `last_entertainment_config_id` from `GET /api/cameras` and writes via `PUT /api/cameras/last-zone/{stable_id}`.

Output: Extended `database.py` schema, three endpoint surfaces in `routers/cameras.py` (one new PUT, one extended GET, and `put_assignment` extended with a last_seen_at bump), and backend tests proving the contract.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-01 | Tampering | `PUT /api/cameras/last-zone/{stable_id}` | mitigate | Validate `stable_id` exists in `known_cameras` before any write; return 404 if missing. Prevents orphan rows keyed by arbitrary attacker-supplied paths. |
| T-16-02 | Tampering | `PUT /api/cameras/last-zone/{stable_id}` body | mitigate | Validate `body.entertainment_config_id` exists in `entertainment_configs` table; return 404 if missing. Prevents garbage foreign-key values. |
| T-16-03 | Information Disclosure | `GET /api/cameras` response | accept | `last_entertainment_config_id` is a UUID, not a secret; no PII. Consistent with existing `zone_health` exposure (same surface). |
| T-16-04 | Denial of Service | `PUT /api/cameras/last-zone/{stable_id}` repeated calls | accept | Unauth LAN tool; single-user; SQLite upsert is O(log n). Worst case is one row rewrite per request — negligible. No rate limiting needed (consistent with existing `put_assignment`). |
| T-16-05 | Repudiation | `camera_last_zone.updated_at` | accept | Server-side timestamp (`datetime.now(timezone.utc).isoformat()`); no user-provided value. Matches `known_cameras.last_seen_at` semantics. |
