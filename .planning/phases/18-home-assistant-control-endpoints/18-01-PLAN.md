Rules:
- DO NOT add `INSERT OR IGNORE INTO ha_state (id) VALUES (1)` afterwards — D-05 mandates lazy row creation. The first `PUT /api/ha/zone` or `PUT /api/ha/camera` will create the row via `INSERT … ON CONFLICT(id) DO UPDATE`. Adding a seed row would silently introduce a default row that Plan 02's tests then have to account for.
- DO NOT add `await db.commit()` after this single statement — `init_db` already does a single commit at the end of all CREATE TABLE statements (verify by reading `database.py` first).
- Use `CHECK (id = 1)` exactly as written — this is the project's single-row enforcement idiom (precedent: `bridge_config` table).
- Use triple-quoted SQL with the four columns in this order: `id`, `active_config_id`, `active_camera_stable_id`, `updated_at`. Plan 02 and Plan 03 will reference these column names verbatim.
