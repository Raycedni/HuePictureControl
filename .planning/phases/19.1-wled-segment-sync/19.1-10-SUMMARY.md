## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Environment portability] PLAN verify command used Linux venv path; ran with Windows venv path instead**
- **Found during:** Task 1 (pre-checkpoint automation gate)
- **Issue:** PLAN.md's `<verify><automated>` block hardcodes `source /tmp/hpc-venv/bin/activate` (Linux convention). Working tree is on Windows under MINGW64 — that file doesn't exist. The Windows-style venv at `/tmp/hpc-venv/Scripts/activate` does exist.
- **Fix:** Ran `source /tmp/hpc-venv/Scripts/activate && cd Backend && python -m pytest --tb=short -q` instead.
- **Files modified:** _(none — runtime adjustment only, plan text not edited)_
- **Verification:** Backend pytest collected and ran 370 tests (337 pass + 21 skip + 12 pre-existing fail).
- **Committed in:** _(no source commit needed; this SUMMARY documents the host-specific path)_

**2. [Rule 4 — Documentation accuracy] V2 spec mentioned 5 segments; device has 4**
- **Found during:** Task 2 (V2 chip-vs-strip parity check)
- **Issue:** PLAN.md V2 specifies configuring 5 segments at non-overlapping ranges (0-29, 30-59, 60-89, 90-119, 120-149) on a 300-LED strip. User's WLED-Gledopto is already configured with 4 segments (Right, Top, Left, Bottom — covering 0-53, 54-149, 150-203, 204-299) matching their physical room layout.
- **Fix:** V2 parity check applied to all 4 existing segments instead of 5 prescribed segments. Same semantic guarantee (every `seg_index` → strip-painter zone color matches LightPanel chip color).
- **Files modified:** _(none — UAT-only adjustment)_
- **Verification:** User signed off `approved` on the full 4-segment parity comparison.
- **Committed in:** _(documented here, not in source)_
