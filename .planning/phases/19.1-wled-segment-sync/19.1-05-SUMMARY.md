### `Backend/services/streaming_coordinator.py`

Two SQL sites rewritten. The Python wrapper code around each (named-parameter bind, async-with cursor, defensive try/except returning `{}` or `[]`, plan-dict / channel-list assembly) is UNCHANGED.

**`_build_region_plan` SQL (D-22):**

Before:
```sql
SELECT DISTINCT r.id AS region_id, r.polygon,
       COALESCE(MAX(wc.end_led - wc.start_led + 1), 1) AS n_region,
       COALESCE(MAX(wla.orientation), 'auto') AS orientation
FROM regions r
LEFT JOIN light_assignments la ON la.region_id = r.id AND la.entertainment_config_id = :cfg
LEFT JOIN wled_light_assignments wla ON wla.region_id = r.id AND wla.entertainment_config_id = :cfg
LEFT JOIN wled_channels wc ON wc.id = wla.wled_channel_id
WHERE la.region_id IS NOT NULL OR wla.region_id IS NOT NULL
GROUP BY r.id, r.polygon
```

After:
```sql
SELECT DISTINCT r.id AS region_id, r.polygon,
       COALESCE(MAX(wsc.stop_led - wsc.start_led + 1), 1) AS n_region,
       COALESCE(MAX(wla.orientation), 'auto') AS orientation
FROM regions r
LEFT JOIN light_assignments la
    ON la.region_id = r.id AND la.entertainment_config_id = :cfg
LEFT JOIN wled_light_assignments wla
    ON wla.region_id = r.id AND wla.entertainment_config_id = :cfg
LEFT JOIN wled_seg_cache wsc
    ON wsc.device_id = wla.wled_device_id
   AND wsc.seg_index = wla.seg_index
WHERE la.region_id IS NOT NULL OR wla.region_id IS NOT NULL
GROUP BY r.id, r.polygon
```

The `+ 1` arithmetic is preserved because both `start_led` and `stop_led` in `wled_seg_cache` are INCLUSIVE (Plan 02 converted the EXCLUSIVE WLED `seg.stop` at the parse boundary, so the same arithmetic holds — only the column names rotate).

**`_load_wled_device_rows` inner SELECT:**

Before:
```sql
SELECT wc.id AS channel_id, wc.start_led, wc.end_led, wla.region_id
FROM wled_channels wc
LEFT JOIN wled_light_assignments wla
    ON wla.wled_channel_id = wc.id
   AND wla.entertainment_config_id = ?
WHERE wc.device_id = ?
```

After:
```sql
SELECT wsc.seg_index, wla.region_id, wsc.start_led, wsc.stop_led
FROM wled_seg_cache wsc
LEFT JOIN wled_light_assignments wla
    ON wla.wled_device_id = wsc.device_id
   AND wla.seg_index = wsc.seg_index
   AND wla.entertainment_config_id = ?
WHERE wsc.device_id = ?
ORDER BY wsc.seg_index
```

Channel-dict assembly downstream:
```python
channels.append({
    "id": str(c["seg_index"]),       # str(int) adapter — preserves WledStreamer contract
    "region_id": c["region_id"],
    "start_led": int(c["start_led"]),
    "end_led": int(c["stop_led"]),   # wsc.stop_led is INCLUSIVE; WledStreamer expects inclusive
})
```

The `ORDER BY wsc.seg_index` was added to make the channel list deterministic — useful for tests that index into `channels[0]`. Both row-key access and positional-tuple fallback are preserved.

**Docstrings updated** in both methods to cite D-22, D-13, RESEARCH.md Open Question #1, and the INCLUSIVE-both-ends invariant.

## Decisions Made

- **`id = str(seg_index)` adapter at the producer boundary.** `WledStreamer.start` expects each channel dict to carry an `id: str` (it keys per-device state on this value). Plan 19.1 collapses the channel UUID onto the integer `seg_index`. Two options were on the table:
  1. **Producer-side adapter (chosen):** the coordinator stringifies `seg_index` -> `id` in one line, no other changes. ~1 LoC.
  2. Refactor WledStreamer to accept `(device_id, seg_index)` tuples and key state on that. ~150+ LoC across `wled_streamer.py` + every test using it.
  Option 1 wins on diff-cost. The cost is one `str()` call per channel per `stream-start` — negligible.
- **`wsc.stop_led` flows through as `end_led` unchanged.** Both columns are INCLUSIVE (Plan 02 converted the EXCLUSIVE WLED `seg.stop` at the parse boundary). No conversion needed at this SQL boundary.
- **Static-source test using `inspect.getsource(module)`.** The first new RED test asserts the SQL string contains specific substrings AND does NOT contain forbidden ones. This pins the structural invariant (no `wled_channels` table, must JOIN `wled_seg_cache`) regardless of how a future refactor formats the SQL — survives whitespace, comment, and alias changes that a behavior-only test would miss.
- **Update the SQL-routing test mocks (not delete them).** `test_frame_loop_passes_region_gradients_to_hue_render` and `test_coordinator_fans_out_to_hue_and_wled` both use SQL-substring routing. Under the new code their `"FROM wled_channels"` branches never fire, and the tests would silently degrade to "fall-through to empty cursor" assertions. Updating the branches in this plan prevents these from becoming silent always-pass tests in the suite — a maintenance hazard worth ~3 minutes of fixture work.
- **Keep the dormant `next_channel_n` column on the e2e `wled_devices` table.** Plan 02 left this column in the production schema as Claude's Discretion per D-10. Including it in the e2e fixture means the router's POST /devices handler (which may write to it in a future test variant) doesn't trip on a missing column. Cost: one extra word in the CREATE.
