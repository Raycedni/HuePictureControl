<objective>
Wave 4 — Editor canvas + popover: convert the drag-drop assignment flow and the region orientation popover from Phase 19's `wled_channel_id` model to Phase 19.1's composite `(wled_device_id, seg_index)` model.

Per RESEARCH.md the three affected files are independent of the Settings tab files in Plan 07 — they touch different files, so the two plans run in parallel in Wave 4.

Three rewrites:

1. **`LightPanel.tsx`** — WLED section: fetch segments via `listSegments` (not `listWledChannels`); rename local state `wledChannelsByDevice` → `wledSegsByDevice`; rewrite drag payload to set `wledDeviceId` + `seg_index` per D-13 of this phase; chip color uses `channelColor(seg.seg_index)`; counter chip counts segments; row display uses `segmentName(seg)` from `@/utils/wled-segment`.

2. **`EditorCanvas.tsx`** — `handleDrop` WLED branch: discriminator changes from `wledChannelId` to `wledDeviceId` (presence-based check); read `seg_index` from `dataTransfer`; POST `upsertWledAssignment({region_id, wled_device_id, seg_index, entertainment_config_id})`; the existing hit-test + setSelectedId + setWledAssignments refetch pattern is preserved byte-for-byte.

3. **`RegionOrientationPopover.tsx`** — channel list reads `(device_id, seg_index)` pairs; chip color via `channelColor(seg_index)`; channel name via `segmentName(seg)`; testids become `region-orientation-popover-chip-{device_id}-{seg_index}`; the Base UI popover + orientation segmented control + virtual-anchor pattern stay byte-for-byte.

Plus test updates in `LightPanel.test.tsx` and `EditorCanvas.test.tsx` to assert the new drag/drop payloads.

Purpose: This plan closes the assignment flow end-to-end (drag from LightPanel → drop on EditorCanvas → POST → popover renders chip → orientation control writes back). After this lands, every UI surface speaks Phase 19.1 vocabulary.

Output: All three component files updated; drag-drop tests assert new payload keys; popover test asserts seg_index-keyed lookups.
</objective>
