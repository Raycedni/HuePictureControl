## Decisions Made

- **EXCLUSIVE→INCLUSIVE at the parse boundary, not the storage boundary.** The conversion happens inside `fetch_wled_state` so every other downstream consumer (reconcile, router, streaming coordinator) speaks the same INCLUSIVE language as Phase 19's `wled_channels.end_led`. Avoids the trap of mixing conventions in the same codebase.
- **`seg.id` is IGNORED.** Per D-11 + WLED docs ("may be omitted") + firmware 0.14 issue #3041 (id can be misleading), the canonical `seg_index` is the array index. A dedicated test (`test_fetch_wled_state_ignores_seg_id_uses_array_index`) pins this behavior.
- **`PRAGMA user_version` over presence-check.** Presence-check would re-fire on every restart and never know whether to drop or skip. `user_version` is a single integer that lives in the file header, no extra table, atomic bump.
- **Bump `user_version` LAST.** Standard idempotent-migration practice — if any DDL between the read and the bump fails, the guard re-fires on next boot and tries again.
- **`next_channel_n` ALTER preserved.** D-10 said Claude's Discretion; keeping the column saves an extra migration and the column is cheap.
- **`orientation NOT NULL DEFAULT 'auto'` is in the CREATE.** Since the new `wled_light_assignments` is created from scratch under the guard, the Phase 19 add-column ALTER is dead code and was removed.
