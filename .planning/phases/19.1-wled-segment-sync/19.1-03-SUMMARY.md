## Decisions Made

- **Cascade uses NOT IN against the freshly-written cache, not the input list.** Steps 1+2 are already serialized inside the implicit transaction, so the sub-SELECT in Step 3 sees the new rows (never the pre-DELETE ones). Simpler than diff-by-set, trivially robust to duplicate `seg_index` in input, mirrors `routers/wled.py:792-798` `cur.rowcount or 0` idiom.
- **`if rows:` guard before `executemany`.** D-15's N→0 path must work cleanly. Guarding the executemany is explicit; the cascade still runs.
- **`int()` coercion inside the row tuple.** Defensive against future callers passing json-derived numeric strings — cheap, no test cost.
- **No network I/O in the service.** RESEARCH.md §"Reconciliation Transaction" → "Why NOT wrap the fetch" rationale: keeps the unit tests `httpx`-free, keeps the transaction window tight, lets the router translate `httpx.HTTPStatusError` / `httpx.ConnectError` / `ValueError` to proper HTTP responses without polluting the service.

## Cascade Ordering Confirmation

The plan output asked specifically to confirm that the cascade delete only fires AFTER successful insert, referencing the freshly-written cache rows.

The implementation guarantees this by ordering inside one transaction:

1. `DELETE FROM wled_seg_cache WHERE device_id = ?` (Step 1)
2. `await db.executemany(...)` if any rows (Step 2)
3. `DELETE FROM wled_light_assignments WHERE wled_device_id = ? AND seg_index NOT IN (SELECT seg_index FROM wled_seg_cache WHERE device_id = ?)` (Step 3)
4. `await db.commit()` (Step 4)

Because Steps 1+2 run before Step 3 within the same implicit transaction, the sub-SELECT inside Step 3 reads the post-Step-2 cache state. If Step 2 inserted seg 0 but not seg 1, the assignment row pointing at seg 1 is the one whose `seg_index` is NOT IN the cache and gets deleted. If Step 2 was skipped (N→0 case), the cache is empty for this device, so every assignment row for this device's `wled_device_id` is in the NOT IN set and gets deleted — `test_reconcile_n_to_zero_wipes_all_assignments` exercises this exact path.

If any of Steps 1-3 raise, `except: await db.rollback()` undoes the entire transaction — no partial cache, no orphan assignments.
