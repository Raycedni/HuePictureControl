## Decisions Made

- **Per-device refresh state lives in the parent (`WledStripPainter`), not in `DeviceStrip`.** `refreshing` and `refreshError` are records keyed by `device_id`. This keeps `DeviceStrip` a pure renderer (props in, JSX out) and lets the parent decide whether to fan refresh-success across the same device's block via `setBlocks(...)`. Alternative: own the state inside DeviceStrip + lift the result via callback. Rejected: would require an extra `onRefreshDone(deviceId, segments)` callback prop and the same record-keyed coordination at the parent anyway.
- **Canvas-zone testid sentinel pattern.** Konva renders zones into a single `<canvas>` element, so `data-testid="wled-seg-{deviceId}-{segIndex}"` on a Konva `Rect` is invisible to testing-library. Solution: mount a zero-pixel `<span data-testid={testId} style={{display:'none'}} aria-hidden>` inside each `<Group>`. In real renders the span is invisible. In the test the react-konva mock passes Group children through as a fragment, so the span becomes a DOM peer the tests can find. The plan's acceptance criteria asserted `grep -c "wled-seg-" >= 1`; this approach satisfies both the grep and the JSDOM-test discovery requirements.
- **Inline `ledToPixel` rather than re-importing from `wled-paint-reducer.ts`.** Plan 09 deletes `wled-paint-reducer.ts` entirely. Importing from it during Plan 07 would create a "will fail" coupling that Plan 09 has to clean up. Inlining the 1-line function removes the dependency and keeps Plan 07 self-contained. `pixelToLed` and `clampBoundary` were paint/boundary-only — no consumer in the read-only strip — so they're not re-introduced anywhere.
- **Dropped `refreshTrigger` counter** from both `SettingsPanel.tsx` and `SettingsPage.tsx`. Phase 19's pattern: sidebar mutates a channel → parent bumps `refreshTrigger` → strip's `useEffect([..., refreshTrigger])` re-fires `reload()`. Phase 19.1 has zero sidebar mutations and the strip owns its own per-device Refresh button, so the trigger counter is dead state. Removing it tightens the contract.
- **Optional Clear-selection button on the sidebar.** D-07 forbids inputs that mutate segment data; a UI-only clear button (it just nullifies the parent's `selectedSeg` state) sits cleanly inside that boundary. Tests assert the callback fires; if reviewers find it objectionable later, it's a 5-line removal.
