## Decisions Made

- **Two-fetch atomic registration BEFORE any DB write.** The plan's Task 1 Step 6 listed two
  alternative orderings (fetch-then-commit-then-reconcile, or fetch+reconcile-then-commit).
  The first was the simpler shape, the second was the strictly-atomic shape. We shipped the
  strictly-atomic one because Task 2's `test_register_device_rolls_back_on_state_failure`
  asserts the strict guarantee — if `/json/state` raises after `/json/info` succeeds, there
  must be ZERO `wled_devices` rows for the IP. Test passing proves the ordering.
- **`reconcile_segments` runs AFTER the device-row commit, not inside the same transaction.**
  Plan 03's reconcile service owns its own commit/rollback. Running it inside a parent
  transaction would require restructuring the service. Acceptable because (a) at registration
  the cache is empty so reconcile is effectively just an INSERT batch, (b) if reconcile fails
  post-device-commit the device row remains and `wled_seg_cache` is empty — D-04 offline
  behavior is "show last-known cache + stale badge", which the frontend handles for any
  empty-cache device. Test `test_register_device_fetches_state` proves the happy path; if
  reconcile failure became a concern we'd need a separate test, but no plan task requested it.
- **Channel-CRUD endpoints fully deleted, not deprecated.** Per D-10 the channel model is gone
  and any client calling `/api/wled/devices/{id}/channels` should fail loud (404) so the
  frontend rewrite (Plans 06-09) can't accidentally rely on it.
- **PATCH orientation accepts `config` as a query param** matching Phase 19's existing
  contract verbatim. The plan's reference body used `config` as a body field; the Phase 19
  endpoint signature on master uses a query param. Kept the existing query-param shape so the
  endpoint contract is binary-compatible with Phase 19's frontend (Plans 06+ will rewrite the
  frontend regardless, but binary-compat keeps the change diff narrow).
- **`_seg_row_to_out` helper accepts both `aiosqlite.Row` AND positional tuples.** The
  production code sets `row_factory = aiosqlite.Row` but tests sometimes hold raw connections.
  Helper has an `isinstance(row, dict) or hasattr(row, 'keys')` check + positional fallback —
  cheap defensive code, no test cost.

## Deviations from Plan

- **[Rule 3 - Blocking] PATCH orientation uses query-param `config` instead of body field.**
  The plan's reference code wrote `body.entertainment_config_id`. The existing Phase 19
  endpoint signature on master takes `config: str` as a query param. Switching to body would
  have broken Phase 19's frontend without a corresponding frontend change. Adapted the
  endpoint to keep the query-param signature; the SQL and behavior contract are identical
  (`UPDATE ... WHERE region_id = ? AND entertainment_config_id = ?`).
  - **Found during:** Task 1, while rewriting the patch_region_orientation handler.
  - **Files modified:** `Backend/routers/wled.py` (signature unchanged from Phase 19;
    only the SQL column rename was applied), `Backend/tests/test_wled_router.py`
    (`test_patch_region_orientation_writes_all_rows` uses
    `?config=cfg-X` URL param, not a body field).
  - **Commit:** `5450de5` (Task 1) + `6ebf18a` (Task 2).
