## Popover deviceChannelIndexById Removal (D-09 Simplification)

Phase 19 needed a per-device sort-position resolver because the channel id was opaque:

```ts
// Phase 19 — DELETED in 19.1
const deviceChannelIndexById = useMemo(() => {
  const out: Record<string, number> = {}
  for (const channels of Object.values(channelsByDevice)) {
    const sorted = channels.slice().sort((a, b) => a.start_led - b.start_led)
    sorted.forEach((ch, idx) => { out[ch.id] = idx })
  }
  return out
}, [channelsByDevice])
```

Phase 19.1 makes this redundant — `seg_index` IS the palette index per D-09. The chip color lookup becomes a one-liner at the render site:

```ts
style={{ background: channelColor(a.seg_index) }}
```

10 lines of useMemo + sort + forEach + dictionary build, gone. Per-device parity (popover chip === LightPanel chip === strip painter zone) is now guaranteed by every surface consuming the same `a.seg_index`.

## Decisions Made

- **Drag payload carries `segmentName(seg)` result, not raw `seg.name`.** The fallback string for null/empty names is computed at the source (LightPanel) so the drop target never needs to import `segmentName`. The receiver — if any future component reads the dataTransfer for display — gets a guaranteed non-empty string.

- **Guard rails on EditorCanvas drop: parsed `seg_index` validated via `Number.isFinite`.** A malformed dataTransfer entry (`'undefined'`, `''`, `'NaN'`) parses to `NaN` and would otherwise be sent to the backend, which would 422. Pin to two new RED tests: missing seg_index → no POST; missing config id → no POST.

- **JSDOM hsl-to-rgb workaround for chip color assertion.** Reading `.style.background` returns the browser-normalized form. Literal `hsl(...)` string compares fail. Rewrote the chip-color test as a pairwise inequality (`chipA.style.background !== chipB.style.background`) — same semantic guarantee (D-09 palette is `seg_index`-driven), JSDOM-stable.

- **Empty-state copy updated for vocab parity.** Popover empty state was "Drag a channel from the LightPanel..." — changed to "Drag a segment...". Header pluralization "channel/channels" → "segment/segments". These are one-string-each diffs but the wording is user-visible.

- **Plan's `segmentName(` ≥ 2 grep count was over-specified.** The helper is called once, result stored in a `displayName` const, then referenced from the JSX label and from the dataTransfer `wledSegName` setData. Count of 1 satisfies functional intent.

- **No popover test added.** The existing `RegionOrientationPopover.test.tsx` is `it.todo`-only. The plan listed acceptance criteria for it but the file is a stub. Production-code correctness is exercised by EditorCanvas Task 2 GREEN tests (the popover prop pipeline flows through them) plus the acceptance grep checks; the popover-specific case coverage stays a stub per CONTEXT.md.
