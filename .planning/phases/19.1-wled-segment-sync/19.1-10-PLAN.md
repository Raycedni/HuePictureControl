  </what-built>
  <how-to-verify>
    **Prerequisites:**
    - A real WLED device on the LAN with the firmware web UI accessible.
    - The backend running natively (`uvicorn main:app --reload --port 8000`).
    - The frontend running (`cd Frontend && npm run dev`, http://localhost:8091).
    - At least one entertainment configuration on the Hue Bridge (TV-Bereich per CLAUDE.md is fine).

    **V1 — Live LED color (D-23)**
    1. Open the WLED device's own web UI (typically http://[device-ip]/). Create a segment covering LEDs 0-29 with the name "TestSegment".
    2. In HuePictureControl, open the WLED tab. If the device is not yet registered, click "Add WLED Device" and enter its IP. The registration handler should fetch `/json/info` AND `/json/state` (Plan 04 D-02) — confirm by watching the backend log for both URLs.
    3. The strip painter should now show one zone labeled "TestSegment" covering the leftmost portion (0-29 / total LED count).
    4. Drag the segment chip from the LightPanel onto a canvas region.
    5. Start streaming. Point a video source (e.g. a still image of pure red) at the capture device. Confirm the physical LED strip's first 30 LEDs are red within ~1 frame.
    **PASS** if LEDs match the region color. **FAIL** if LEDs are off-color or off-position by more than one LED.

    **V2 — Chip-vs-strip color parity (D-23, D-09)**
    1. On the WLED device, configure 5 segments at non-overlapping ranges (e.g. 0-29, 30-59, 60-89, 90-119, 120-149).
    2. Click the per-device Refresh button in HuePictureControl. The strip painter should render 5 distinct zones.
    3. Open the Editor / LightPanel. The WLED section should list 5 entries.
    4. For each `seg_index` ∈ {0, 1, 2, 3, 4}: visually compare the strip's zone color (in the WLED tab) with the LightPanel chip color (in the Editor). They MUST match.
    **PASS** if all 5 pairs match. **FAIL** if any pair differs.

    **V3' — Refresh roundtrip after WLED-side boundary change (D-23, D-02, D-14, D-16)**
    1. Configure two adjacent segments on the WLED device: seg 0 covers 0-29, seg 1 covers 30-59.
    2. Click Refresh in HuePictureControl. Confirm both zones render at their correct ranges.
    3. Switch to the WLED device's web UI. Change seg 0's stop to 19 and seg 1's start to 20 (boundary shifted from 30 to 20).
    4. Back in HuePictureControl, click Refresh. The strip painter should re-render with seg 0 covering 0-19 (smaller) and seg 1 covering 20-59 (larger).
    5. If a region was assigned to either segment, the assignment should survive (no toast about "removed N stale assignments"). The strip's color rendering for that region should continue to use the new ranges on the next streaming tick.
    **PASS** if ranges re-render correctly and assignments survive. **FAIL** if ranges are stale or assignments dropped.

    **V4 — Full-stack restart persistence (D-23, D-12, D-20)**
    1. Register a WLED device.
    2. Click Refresh once (populates `wled_seg_cache`).
    3. Drag a segment chip onto a canvas region.
    4. Open the region's orientation popover and change to a non-default value (e.g. "left-to-right").
    5. Stop the backend (Ctrl+C in the uvicorn terminal). Stop the frontend dev server.
    6. Restart the backend (`uvicorn main:app --reload --port 8000`).
    7. Restart the frontend (`npm run dev`).
    8. Reload the browser. Open the WLED tab.
    9. Without clicking Refresh, the strip painter should show the cached segments. The Editor canvas should show the region's WLED arrow. The orientation popover should show "left-to-right" still selected.
    **PASS** if strip layout + assignment + orientation all survive without a Refresh click. **FAIL** if any state was lost.

    **Documentation:**
    For each item, record in the summary:
    - PASS / FAIL
    - Date/time of test
    - Any anomalies observed (even on PASS)
    - The WLED firmware version (`GET http://[device-ip]/json/info` → `ver` field)

    **If any item FAILS:** do NOT mark the phase complete. Open a follow-up plan to remediate the specific failure.
  </how-to-verify>
