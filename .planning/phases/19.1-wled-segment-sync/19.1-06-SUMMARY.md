## Decisions Made

- **`patchRegionOrientation` body shape preserved per Plan 04 deviation.** The Plan 06 reference code in the plan body listed the request body as `{orientation, entertainment_config_id}`. The actual backend contract (and Plan 04's deviation note) is `?config=` query param + `{orientation}` body. Preserved the existing client signature `patchRegionOrientation(regionId, configId, orientation)` so the call sites in `RegionOrientationPopover.tsx` keep working post-Wave-4 without a second rewrite.
- **`useRegionStore.ts` body unchanged — type-only propagation.** Per RESEARCH.md the slice never unpacked `wled_channel_id` directly. The `import type { WledAssignment }` line is the single seam; the reshape inside `api/wled.ts` ripples through the slice's `wledAssignments: Record<string, WledAssignment[]>` field and the `updateWledAssignmentOrientation` updater body without code edits. TS `tsc --noEmit -p tsconfig.app.json` produces zero errors in `src/store/` after the rewrite.
- **TDD discipline kept per task.** Two RED commits (`93389a3` for the helper test, `72fc4d6` for the api tests) precede their GREEN counterparts (`454d273`, `29fafb2`). Each RED commit was verified to fail on the intended assertion before its corresponding GREEN commit.
- **`deleteWledAssignment` 204-handling simplified.** Plan's reference code: `if (!res.ok && res.status !== 204) throw`. Actual: `if (!res.ok) throw`. `res.ok` is true for any 2xx response including 204, so the `&& res.status !== 204` term is dead. Test `deleteWledAssignment accepts 204 No-Content as success` proves the simpler guard works.
