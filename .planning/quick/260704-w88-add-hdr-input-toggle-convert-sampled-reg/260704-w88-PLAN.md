<objective>
Add an "HDR input" toggle. When enabled, sampled region colors are converted from HDR10
(BT.2020 primaries + PQ/ST-2084 transfer) to sRGB before saturation boost and rgb_to_xy,
fixing washed-out / hue-rotated output when the capture card passes HDR10 through unconverted
(orange reading as green under saturation boost).

The conversion is applied ONLY to the handful of sampled colors per region per frame (the
(N,3) gradient arrays), never the full frame — preserving the <100ms latency budget.

Purpose: Correct color when the HDMI source is HDR10 and the pipeline currently treats
decoded frames as sRGB.
Output: A new vectorized `hdr10_to_srgb` color-math function, a boolean `hdr_input` KV
setting wired through storage + API + app.state + streaming pipeline, and a frontend toggle
mounted next to the existing vibrancy/saturation controls.
</objective>

Add a module-level function `hdr10_to_srgb(rgb: np.ndarray) -> np.ndarray` to color_math.py
(place it in a new "HDR10 -> sRGB conversion (quick-task 260704-w88)" section near the other
vectorized helpers). It operates on the SAMPLED colors only — a small (N,3) uint8 array — and
must be fully numpy-vectorized. Steps (all on float32, RGB order):

  1. Normalize uint8 → E in [0,1]: `arr = np.asarray(rgb, dtype=np.float32) / 255.0`
     (handle a (3,) input by reshaping to (1,3), remember to restore shape on return).
  2. PQ EOTF (ST 2084 inverse), constants:
     m1=0.1593017578125, m2=78.84375, c1=0.8359375, c2=18.8515625, c3=18.6875
     `ep = E ** (1.0/m2)`
     `linear = (np.maximum(ep - c1, 0.0) / (c2 - c3*ep)) ** (1.0/m1)`
     linear is now in [0,1] representing 0..10000 nits.
  3. Scale to reference white: `rel = linear * (10000.0 / 203.0)` (203 nits SDR reference
     white → rel≈1.0 at diffuse white; expose 203.0 as a module constant HDR_REF_WHITE_NITS).
  4. BT.2020 → BT.709 3x3 matrix (per (N,3) via `rel @ M.T`):
     M = [[1.6605,-0.5876,-0.0728],[-0.1246,1.1329,-0.0083],[-0.0182,-0.1006,1.1187]]
     (store as module-level float32 array, mirroring _WIDE_RGB_D65).
  5. Clip negatives: `rel709 = np.maximum(rel709, 0.0)`.
  6. Simple Reinhard-style highlight roll-off (extended Reinhard so mid-tones stay near-linear
     and only highlights >1 compress; maps HDR_WHITE→1.0):
     `white = 10000.0 / 203.0`
     `toned = rel709 * (1.0 + rel709 / (white*white)) / (1.0 + rel709)`
     Applied per-channel is acceptable (matches the reference); the neutral/hue invariants in
     <behavior> are what define correctness, the exact curve is discretion within these bounds.
  7. sRGB OETF encode (inverse of _gamma_expand):
     `srgb = np.where(toned > 0.0031308, 1.055 * (toned ** (1.0/2.4)) - 0.055, 12.92 * toned)`
  8. `out = np.clip(srgb, 0.0, 1.0) * 255.0`; round → uint8; restore original ndim.

Then write the known-value tests described in <behavior> into test_color_math.py (add a new

assertions, not brittle exact-equality on the tone-map curve.

Do NOT touch the full-frame path or any other color_math function.
