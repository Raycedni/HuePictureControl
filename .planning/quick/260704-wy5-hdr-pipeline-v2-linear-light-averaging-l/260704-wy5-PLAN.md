<objective>
HDR pipeline v2: move HDR expansion+decode BEFORE region averaging so region means
are computed in LINEAR light. Fixes murky warm-gray output on high-dynamic-range
scenes where the v1 pipeline (which converted AFTER averaging over PQ-encoded bytes)
let a bright fire barely outweigh a dull sail, collapsing means to warm gray.

Purpose: A bright area should dominate a region's mean the way it dominates
perceptually (~10x in linear light, not ~1.7x in PQ-byte space). Also corrects the
capture card's limited-range signal (blacks ~16, whites ~217) which v1 mis-treated
as full-range.

Output:
- A module-level 256-entry float32 LUT (limited-range expansion -> PQ EOTF -> linear,
  same nits scaling as v1) applied per-pixel on the region ROI.
- A finishing function for (N,3) linear BT.2020 means (roll-off -> BT.2020->BT.709
  matrix -> clip -> sRGB encode -> uint8).
- An `hdr: bool = False` param on extract_region_color and sub_sample_gradient that
  averages in linear light when True, byte-identical current behavior when False.
- streaming_coordinator threads `hdr` into the sampling calls and drops the post-hoc
  hdr10_to_srgb wrapping.
</objective>

Current v1 hdr10_to_srgb pipeline (float32, RGB order), to be DECOMPOSED:
  1. normalize uint8 -> [0,1]  (FULL range /255)
  2. PQ EOTF (ST 2084 inverse) -> linear [0,1]
  3. rel = linear * (10000/HDR_REF_WHITE_NITS)
  4. extended-Reinhard roll-off in BT.2020 gamut: toned = rel*(1+rel/(white*white))/(1+rel), white=10000/203
  5. rel709 = toned @ _BT2020_TO_BT709.T
  6. rel709 = max(rel709, 0.0)
  7. sRGB OETF: where(x>0.0031308, 1.055*x**(1/2.4)-0.055, 12.92*x); clip[0,1]*255; round; uint8

Current sampling signatures:
```python
def extract_region_color(frame, region: RegionMask, vibrancy: float = 0.0) -> tuple[int,int,int]
def sub_sample_gradient(frame, region, n, orientation="auto", vibrancy: float = 0.0) -> np.ndarray  # (n,3) uint8 RGB
def _saturation_weights(roi_bgr, alpha) -> np.ndarray            # (H,W) float32; works on any float dtype
def _weighted_region_mean(roi_bgr, mask, weights) -> tuple[int,int,int]  # uint8 RGB, luma-preserving
```

CRITICAL channel-order fact: `frame` is BGR (OpenCV capture). The LUT is per-byte
(channel-agnostic), so `_LINEAR_LUT[roi_frame]` yields linear values in BGR order.
Reorder BGR->RGB (slice `[..., ::-1]`) before the finishing function, which expects
RGB (the BT.2020->BT.709 matrix is RGB-order). Non-hdr paths already do this reorder
when returning (mean[2],mean[1],mean[0]).
